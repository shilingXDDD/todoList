## 一、ViewModel + Repository（2 分）⭐

### 1.1 为什么值得先做

评分表原文：「使用 ViewModel 与 Repository，分层架构，Activity/Fragment 不直接承担全部数据逻辑」。

**顺带解决三个已有问题**：

| 问题 | ViewModel 如何解决 |
|---|---|
| 转屏后数据重新加载、列表闪一下 | ViewModel 在配置变化时**不被销毁** |
| Fragment 里堆了大量数据库调用 | 挪到 ViewModel，页面只管显示 |
| 横竖屏输入内容丢失（附加 2 分） | 用 ViewModel 保存 |

### 1.2 加依赖

📁 `app/build.gradle.kts` 的 `dependencies { }` 里加：

```kotlin
implementation("androidx.lifecycle:lifecycle-viewmodel-ktx:2.6.2")
implementation("androidx.lifecycle:lifecycle-runtime-ktx:2.6.2")
implementation("androidx.activity:activity-ktx:1.8.0")   // Activity 的 by viewModels()
```

> 📌 **当前实际状态**：`build.gradle.kts` 里**还没有**这三行。
> 你项目里有 `androidx.fragment:fragment-ktx:1.6.2`，它会**传递依赖**
> lifecycle-runtime / lifecycle-viewmodel，所以 `repeatOnLifecycle` 现在能用。
> 但**显式声明是规范要求**（答辩可能被问到架构分层），建议加上。
>
> 加完记得 **Sync Now**，否则新增的依赖不生效。

⚠️ `by viewModels()` 有两个来源，别导错包：

| 用在 | import |
|---|---|
| Fragment | `androidx.fragment.app.viewModels` |
| Activity | `androidx.activity.viewModels` |

### 1.3 建 ViewModel

`ui/list/TaskListViewModel.kt`：

```kotlin
package com.example.todo_list.ui.list

import androidx.lifecycle.ViewModel
import androidx.lifecycle.viewModelScope
import com.example.todo_list.data.Task
import com.example.todo_list.data.TaskRepository
import kotlinx.coroutines.flow.SharingStarted
import kotlinx.coroutines.flow.StateFlow
import kotlinx.coroutines.flow.stateIn
import kotlinx.coroutines.launch

class TaskListViewModel : ViewModel() {

    // 把 Flow 转成 StateFlow，暴露给 UI
    val tasks: StateFlow<List<Task>> = TaskRepository.getTasks()
        .stateIn(
            scope = viewModelScope,
            started = SharingStarted.WhileSubscribed(5000),
            initialValue = emptyList()
        )

    fun toggleCompleted(task: Task) {
        viewModelScope.launch {
            TaskRepository.updateTask(task.copy(isCompleted = !task.isCompleted))
        }
    }

    fun deleteTask(task: Task) {
        viewModelScope.launch {
            TaskRepository.deleteTask(task)
        }
    }
}
```

⚠️ **`viewModelScope` 会自动取消**：页面销毁时，这个作用域里的所有协程自动取消，不需要你手动管理——这是它比 `lifecycleScope` 更适合放数据逻辑的原因。

### 1.4 Fragment 改成用 ViewModel

```kotlin
class TaskListFragment : Fragment() {

    private val viewModel: TaskListViewModel by viewModels()
    // ...

    private fun observeTasks() {
        viewLifecycleOwner.lifecycleScope.launch {
            repeatOnLifecycle(Lifecycle.State.STARTED) {
                viewModel.tasks.collect { tasks ->
                    taskAdapter.submitList(tasks)
                    binding.emptyTextView.visibility =
                        if (tasks.isEmpty()) View.VISIBLE else View.GONE
                }
            }
        }
    }

    private fun setupRecyclerView() {
        taskAdapter = TaskAdapter(
            onItemClick = { TaskDetailActivity.startUI(requireContext(), it.id) },
            onCheckedChange = { task, _ -> viewModel.toggleCompleted(task) }
        )
        binding.taskRecyclerView.adapter = taskAdapter
    }
}
```

需要 import：

```kotlin
import androidx.fragment.app.viewModels
```

⚠️ 上面这段里的 `keyword` 来自**第四步的搜索功能**。如果还没做搜索，
把 `keyword` 相关代码去掉即可，ViewModel 的用法不变。

**变化**：Fragment 里不再出现 `TaskRepository`，只有 `viewModel`——这就是"分层"的体现，也是这 2 分的判据。

> 📌 **踩坑记录**：`stateIn` 的参数顺序容易记混，正确顺序是
> `scope` → `started` → `initialValue`。写成 `stateIn(initialValue, scope, started)`
> 会编译报错（参数顺序不对 + 类型不匹配）。

## 二、横竖屏状态恢复（2 分）

评分表：「重建后页面状态、输入内容、当前数据不丢失」。

### 2.1 最容易拿分的做法：给 EditText 加 id

Android 系统**只对有 `android:id` 的 View 自动保存/恢复状态**。

你的 `activity_task_edit.xml` 里 `titleEditText`、`descriptionEditText` 都已有 id，所以**输入内容转屏后会自动保留**——这 2 分其实已经拿了一半，去转屏验证一下即可。

⚠️ 前提是 Activity 在 Manifest 里**没有**设置 `android:configChanges`。如果设了，系统不重建，但你要自己处理布局切换——反而不如让它重建。检查一下你的 Manifest 没有这个属性。

### 2.2 ViewModel 保住数据

列表数据用 ViewModel 持有后，转屏不会重新查库。

### 2.3 手动保存（可选）

如果有自定义状态要存：

```kotlin
override fun onSaveInstanceState(outState: Bundle) {
    super.onSaveInstanceState(outState)
    outState.putString("keyword", keyword)
}

override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
    // ...
    keyword = savedInstanceState?.getString("keyword").orEmpty()
}
```

### 2.4 验证

- 编辑页输入一半 → 转屏 → 内容还在
- 列表页滚到中间 → 转屏 → 位置还在（ViewModel 保住了数据，不会从头加载）

## 三、深色模式（2 分）

### 3.1 现状

经过「滴答清单风格 UI 重构」之后，主题结构是这样的：

- `values/themes.xml` → `Theme.Todolist`，parent 是
  `Theme.MaterialComponents.Light.NoActionBar`，**固定亮色，不支持深色**
- `values/styles.xml` → 卡片 / 按钮 / 输入框 / 底部导航 / FAB 等样式集中在这里
- `values/colors.xml` → 浅灰白背景 `#F7F8FA` + 清爽蓝 `#4A90E2`

要拿这 2 分，两种做法：

| 做法 | 说明 |
|---|---|
| **A. 跟随系统** | 改回 DayNight 主题 + 建 `values-night/colors.xml` |
| **B. 手动切换** | 在设置页加开关，代码切换 |

⚠️ **重要**：网上很多教程让你在 `values-night/themes.xml` 里写
`@color/purple_200`、`@color/purple_700`——**千万别照抄**。
UI 重构后 `colors.xml` 里这两个颜色**已经删除**，写了会直接爆红
「AAPT: resource color/purple_200 not found」，整个项目编译不过。

> 📌 **踩坑记录**：本文档早期版本正是这么写的，属于照抄入门模板留下的坑。
> 你项目的颜色体系早已不是默认的紫色了。

📌 **设置页的入口已经留好了**：`fragment_settings.xml` 里有 `txvGroupAppearance`
（"外观"分组标题）和 `cardAppearance`（深色模式 / 统计两个条目），默认 `gone`。
做深色模式时把这两处改成 `visible` 即可，条目样式（细分割线 + `>` 箭头）都是现成的。

### 3.2 做法 A：跟随系统

**第 ① 步：`values/themes.xml` 只改一行 parent**

```xml
<style name="Theme.Todolist" parent="Theme.MaterialComponents.DayNight.NoActionBar">
```

其余**全部不用动**——因为控件样式已经收口到 `styles.xml` 了。

**第 ② 步：新建 `values-night/colors.xml`，覆盖同名颜色**

这是 UI 重构带来的最大好处：**不用写两套 styles**。
`styles.xml` 里所有样式都通过 `@color/xxx` 引用颜色，
只要在 `values-night` 里覆盖同名颜色，卡片、按钮、输入框会自动跟着变深色。

📁 新建 `app/src/main/res/values-night/colors.xml`：

```xml
<resources>
    <!-- 背景与表面 -->
    <color name="background">#FF121212</color>
    <color name="surface">#FF1E1E1E</color>
    <color name="card_background">#FF1E1E1E</color>

    <!-- 主色保持蓝色调，深色下略提亮保证对比度 -->
    <color name="primary">#FF6BA6EE</color>
    <color name="primary_dark">#FF4A90E2</color>
    <color name="primary_light">#FF1E3A5F</color>
    <color name="primary_on_light">#FF9CCBFA</color>

    <!-- 文字：直接复用 colors.xml 里已定义好的深色版 -->
    <color name="text_primary">@color/text_primary_dark</color>
    <color name="text_secondary">@color/text_secondary_dark</color>
    <color name="text_hint">#FF6B7280</color>
    <color name="text_disabled">#FF5A6068</color>

    <!-- 分割线 / 描边 -->
    <color name="divider">#FF2A2A2A</color>
    <color name="border">#FF3A3A3A</color>

    <!-- 圆形复选框未选中的描边 -->
    <color name="checkbox_unchecked_stroke">#FF5A6068</color>
</resources>
```

⚠️ `text_primary_dark` / `text_secondary_dark` 在 `values/colors.xml` 里**已经定义好了**，
这里直接引用而不是重复写色值——否则以后改色要改两处。

**第 ③ 步（可选）：`values-night/themes.xml`**

只覆盖颜色通常就够了，**这个文件可以不建**。
只有想单独调状态栏时才需要：

```xml
<resources>
    <style name="Theme.Todolist" parent="Theme.MaterialComponents.DayNight.NoActionBar">
        <item name="android:statusBarColor">#FF121212</item>
        <item name="android:windowLightStatusBar">false</item>
        <item name="android:navigationBarColor">#FF121212</item>
        <item name="android:windowLightNavigationBar">false</item>
    </style>
</resources>
```

⚠️ 深色模式下 `windowLightStatusBar` / `windowLightNavigationBar` 必须设成 `false`
（图标变白）。不改的话深色背景上还是深色图标，看不清——**这是最容易漏的一处**。

⚠️ `alertDialogTheme` 在 `values/themes.xml` 里已经统一指向
`ThemeOverlay.App.Dialog.Alert`，DayNight 会自动选深浅版本，
**不要**在 night 里改成 `Theme.AppCompat.Dialog.Alert`（那是 AppCompat 时代的写法，
和 MaterialComponents 混用会导致对话框按钮文字颜色异常）。

### 3.3 做法 B：手动切换（设置页开关）

```kotlin
// 开
AppCompatDelegate.setDefaultNightMode(AppCompatDelegate.MODE_NIGHT_YES)
// 关
AppCompatDelegate.setDefaultNightMode(AppCompatDelegate.MODE_NIGHT_NO)
// 跟随系统
AppCompatDelegate.setDefaultNightMode(AppCompatDelegate.MODE_NIGHT_FOLLOW_SYSTEM)
```

配合 SP 记住开关状态（复用你已会的方法）。

### 3.4 必须检查的硬编码颜色

⚠️ 深色模式下最常见的 bug 是**白底白字**——因为某处写死了 `#FFFFFF`。

检查两个地方：

**① 布局里的 `android:textColor`**

凡是写死的改成主题属性：

```xml
android:textColor="?android:attr/textColorPrimary"    <!-- ✅ -->
android:textColor="#FF000000"                          <!-- ❌ -->
```

**② drawable 里的矢量图**

要分成两批看，因为 UI 重构时新增了一批图标，写法和原来的不一样：

| 批次 | 图标 | 写法 | 深色下怎么办 |
|---|---|---|---|
| **原有图标** | `ic_check`、`ic_delete`、`ic_edit`、`ic_arrow_back`、`ic_notification` 等 | `?attr/colorOnSurface` | ✅ **不用改**，自动变白 |
| **UI 重构新增** | `ic_checkbox_unchecked`、`ic_chevron_right`、`ic_empty_task`、`ic_person`、`ic_checkbox_checked_circle` | `@color/xxx` | ⚠️ 靠 `values-night/colors.xml` 覆盖 |

新增这批用的颜色分别是：

- `ic_checkbox_unchecked.xml` → `@color/checkbox_unchecked_stroke`
- `ic_chevron_right.xml` / `ic_empty_task.xml` → `@color/text_hint`
- `ic_person.xml` / `ic_checkbox_checked_circle.xml` → `@color/primary`
- `bg_pill_blue.xml` / `bg_status_badge.xml` / `bg_circle_avatar.xml` → `@color/primary_light`

只要 3.2 第 ② 步的 `values-night/colors.xml` 建好了，这些都会自动变，**不用逐个改**。

❌ **唯一例外**：`ic_add.xml`（FAB 的加号）写的是 `@android:color/white`。
这是**故意的**——FAB 背景深浅都是主题蓝，加号永远白色，不用改。

### 3.5 验证

- 系统切深色 → App 变深色
- 列表、详情、设置三个页面**文字都看得清**
- 没有某块区域是「黑底黑字」或「白底白字」

import androidx.test.core.app.ApplicationProvider

import org.junit.Assert.assertNotNull
import org.junit.Before
import org.junit.Test
import org.junit.runner.RunWith

@RunWith(AndroidJUnit4::class)
class TaskDaoTest {

    private lateinit var db: AppDatabase
    private lateinit var dao: TaskDao

        db = Room.inMemoryDatabaseBuilder(context, AppDatabase::class.java)

    @After

## 五、ContentProvider（4 分，可选）

工作量最大，**建议最后有余力再做**。

### 5.1 建 Provider

📁 `app/src/main/java/com/example/todo_list/provider/TaskProvider.kt`

```kotlin
package com.example.todo_list.provider

import android.content.ContentProvider
import android.content.ContentUris
import android.content.ContentValues
import android.content.UriMatcher
import android.database.Cursor
import android.database.MatrixCursor
import android.net.Uri
import com.example.todo_list.data.AppDatabase
import com.example.todo_list.data.TaskDao
import kotlinx.coroutines.flow.first
import kotlinx.coroutines.runBlocking

class TaskProvider : ContentProvider() {

    companion object {
        const val AUTHORITY = "com.example.todo_list.provider"
        val URI_TASKS: Uri = Uri.parse("content://$AUTHORITY/tasks")
    }

    private lateinit var dao: TaskDao

    override fun onCreate(): Boolean {
        // ⚠️ context 理论上可能为 null，判空更稳
        val ctx = context ?: return false
        dao = AppDatabase.getInstance(ctx).taskDao()
        return true
    }

    override fun query(uri: Uri, projection: Array<out String>?, selection: String?,
                       selectionArgs: Array<out String>?, sortOrder: String?): Cursor? {
        // 用 MatrixCursor 把 List<Task> 包装成 Cursor
        val cursor = MatrixCursor(arrayOf("id", "title", "description", "isCompleted"))
        // 同步查一次（Provider 不在主线程，且需同步返回）
        val tasks = runBlocking { dao.getAllTasks().first() }
        tasks.forEach {
            cursor.addRow(arrayOf(it.id, it.title, it.description, if (it.isCompleted) 1 else 0))
        }
        return cursor
    }

    override fun insert(uri: Uri, values: ContentValues?): Uri? { /* ... */ }
    override fun delete(uri: Uri, selection: String?, selectionArgs: Array<out String>?): Int { /* ... */ }
    override fun update(uri: Uri, values: ContentValues?, selection: String?,
                        selectionArgs: Array<out String>?): Int { /* ... */ }

    override fun getType(uri: Uri): String = "vnd.android.cursor.dir/vnd.$AUTHORITY.tasks"
}
```

⚠️ **ContentProvider 的 `query` 必须同步返回 Cursor**，但你的 Dao 返回 Flow。要用 `runBlocking { flow.first() }` 取一次快照——这是 Provider 里的特例，和"数据库不能在协程外调用"不冲突。

### 5.2 Manifest 注册

```xml
<provider
    android:name=".provider.TaskProvider"
    android:authorities="com.example.todo_list.provider"
    android:exported="true" />
```

⚠️ ContentProvider 要能被其他 App 访问，`exported` 通常是 `true`。

### 5.3 ContentObserver（1 分）

在列表页注册，监听数据变化。需要 import：

代码：

```kotlin
private val observer = object : ContentObserver(Handler(Looper.getMainLooper())) {
    override fun onChange(selfChange: Boolean) {
        // 数据变了，刷新
    }
}

override fun onStart() {
    super.onStart()
    requireContext().contentResolver
        .registerContentObserver(TaskProvider.URI_TASKS, true, observer)
}

override fun onStop() {
    super.onStop()
    requireContext().contentResolver.unregisterContentObserver(observer)
}
```

⚠️ 和广播一样，**注册就要记得注销**。

⚠️ `ContentObserver` 是 `android.database.ContentObserver`，
不是 `androidx` 包下的，导错会报「Unresolved reference」。

同时 Provider 里数据变化时要通知：

```kotlin
context.contentResolver.notifyChange(uri, null)
```
