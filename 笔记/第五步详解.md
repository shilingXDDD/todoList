## 一、ViewModel + Repository（2 分）⭐

### 1.1 为什么值得先做

评分表原文：「使用 ViewModel 与 Repository，分层架构，Activity/Fragment 不直接承担全部数据逻辑」。

**顺带解决三个已有问题**：

| 问题 | ViewModel 如何解决 |
|---|---|
| 转屏后数据重新加载、列表闪一下 | ViewModel 在配置变化时**不被销毁** |
| Fragment 里堆了大量数据库调用 | 挪到 ViewModel，页面只管显示 |
| 横竖屏输入内容丢失（附加 2 分） | 用 ViewModel 保存 |

### 1.2 加依赖

```kotlin
implementation("androidx.lifecycle:lifecycle-viewmodel-ktx:2.6.2")
implementation("androidx.lifecycle:lifecycle-runtime-ktx:2.6.2")
implementation("androidx.activity:activity-ktx:1.8.0")   // 提供 by viewModels()
```

### 1.3 建 ViewModel

`ui/list/TaskListViewModel.kt`：

```kotlin
package com.example.todo_list.ui.list

import androidx.lifecycle.ViewModel
import androidx.lifecycle.viewModelScope
import com.example.todo_list.data.Task
import com.example.todo_list.data.TaskRepository
import kotlinx.coroutines.launch

class TaskListViewModel : ViewModel() {

    // 把 Flow 转成 StateFlow，暴露给 UI
    val tasks = TaskRepository.getTasks()
        .stateIn(
            scope = viewModelScope,
            started = SharingStarted.WhileSubscribed(5000),
            initialValue = emptyList()
        )

    fun toggleCompleted(task: Task) {
        viewModelScope.launch {
            TaskRepository.updateTask(task.copy(isCompleted = !task.isCompleted))
        }
    }

    fun deleteTask(task: Task) {
        viewModelScope.launch {
            TaskRepository.deleteTask(task)
        }
    }
}
```

⚠️ **`viewModelScope` 会自动取消**：页面销毁时，这个作用域里的所有协程自动取消，不需要你手动管理——这是它比 `lifecycleScope` 更适合放数据逻辑的原因。

### 1.4 Fragment 改成用 ViewModel

```kotlin
class TaskListFragment : Fragment() {

    private val viewModel: TaskListViewModel by viewModels()
    // ...

    private fun observeTasks() {
        viewLifecycleOwner.lifecycleScope.launch {
            repeatOnLifecycle(Lifecycle.State.STARTED) {
                viewModel.tasks.collect { tasks ->
                    taskAdapter.submitList(tasks)
                    binding.emptyTextView.visibility =
                        if (tasks.isEmpty()) View.VISIBLE else View.GONE
                }
            }
        }
    }

    private fun setupRecyclerView() {
        taskAdapter = TaskAdapter(
            onItemClick = { TaskDetailActivity.startUI(requireContext(), it.id) },
            onCheckedChange = { task, _ -> viewModel.toggleCompleted(task) }
        )
        binding.taskRecyclerView.adapter = taskAdapter
    }
}
```

需要 import `androidx.fragment.app.viewModels`。

**变化**：Fragment 里不再出现 `TaskRepository`，只有 `viewModel`——这就是"分层"的体现，也是这 2 分的判据。

## 二、横竖屏状态恢复（2 分）

评分表：「重建后页面状态、输入内容、当前数据不丢失」。

### 2.1 最容易拿分的做法：给 EditText 加 id

Android 系统**只对有 `android:id` 的 View 自动保存/恢复状态**。

你的 `activity_task_edit.xml` 里 `titleEditText`、`descriptionEditText` 都已有 id，所以**输入内容转屏后会自动保留**——这 2 分其实已经拿了一半，去转屏验证一下即可。

⚠️ 前提是 Activity 在 Manifest 里**没有**设置 `android:configChanges`。如果设了，系统不重建，但你要自己处理布局切换——反而不如让它重建。检查一下你的 Manifest 没有这个属性。

### 2.2 ViewModel 保住数据

列表数据用 ViewModel 持有后，转屏不会重新查库。

### 2.3 手动保存（可选）

如果有自定义状态要存：

```kotlin
override fun onSaveInstanceState(outState: Bundle) {
    super.onSaveInstanceState(outState)
    outState.putString("keyword", keyword)
}

override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
    // ...
    keyword = savedInstanceState?.getString("keyword").orEmpty()
}
```

### 2.4 验证

- 编辑页输入一半 → 转屏 → 内容还在
- 列表页滚到中间 → 转屏 → 位置还在（ViewModel 保住了数据，不会从头加载）

## 三、深色模式（2 分）

### 3.1 现状

你的主题是 `Theme.MaterialComponents.Light.NoActionBar`（第二步换的），**固定亮色**，不支持深色。

要拿这 2 分，两种做法：

| 做法 | 说明 |
|---|---|
| **A. 跟随系统** | 改回 DayNight 主题 + 建 `values-night` |
| **B. 手动切换** | 在设置页加开关，代码切换 |

⚠️ 注意：当初换 Light 是为了解决「AlertDialog 发暗」。改回 DayNight 时，**必须同时建 `values-night/themes.xml`**，否则深色模式下对话框和内容又不一致了。

### 3.2 做法 A：跟随系统

`values/themes.xml` 改 parent：

```xml
<style name="Theme.Todolist" parent="Theme.MaterialComponents.DayNight.NoActionBar">
```

新建 `values-night/themes.xml`，把颜色换成深色版：

```xml
<resources>
    <style name="Theme.Todolist" parent="Theme.MaterialComponents.DayNight.NoActionBar">
        <item name="colorPrimary">@color/purple_200</item>
        <item name="colorPrimaryVariant">@color/purple_700</item>
        <item name="colorOnPrimary">@color/black</item>
        <item name="android:windowBackground">@color/background_dark</item>
        <item name="colorSurface">@color/surface_dark</item>
        <item name="colorOnSurface">@color/white</item>
        <item name="android:textColorPrimary">@color/white</item>
        <item name="android:textColorSecondary">@color/text_secondary_dark</item>
        <item name="android:statusBarColor">@color/background_dark</item>
        <item name="alertDialogTheme">@style/Theme.AppCompat.Dialog.Alert</item>
    </style>
</resources>
```

⚠️ 注意 `alertDialogTheme` 在 night 下要用**深色版** `Theme.AppCompat.Dialog.Alert`（没有 `.Light.`），保持一致。

### 3.3 做法 B：手动切换（设置页开关）

```kotlin
// 开
AppCompatDelegate.setDefaultNightMode(AppCompatDelegate.MODE_NIGHT_YES)
// 关
AppCompatDelegate.setDefaultNightMode(AppCompatDelegate.MODE_NIGHT_NO)
// 跟随系统
AppCompatDelegate.setDefaultNightMode(AppCompatDelegate.MODE_NIGHT_FOLLOW_SYSTEM)
```

配合 SP 记住开关状态（复用你已会的方法）。

### 3.4 必须检查的硬编码颜色

⚠️ 深色模式下最常见的 bug 是**白底白字**——因为某处写死了 `#FFFFFF`。

检查两个地方：

**① 布局里的 `android:textColor`**

凡是写死的改成主题属性：

```xml
android:textColor="?android:attr/textColorPrimary"    <!-- ✅ -->
android:textColor="#FF000000"                          <!-- ❌ -->
```

**② drawable 里的矢量图**

你那 12 个图标用的是 `?attr/colorOnSurface`，**已经是主题属性，不用改**——deep 模式自动变白。之前的设计选对了。

### 3.5 验证

- 系统切深色 → App 变深色
- 列表、详情、设置三个页面**文字都看得清**
- 没有某块区域是「黑底黑字」或「白底白字」

## 四、单元测试（2 分）

评分表：「**至少完成一个可运行的测试**」——门槛很低。

### 4.1 加依赖

```kotlin
testImplementation("junit:junit:4.13.2")                    // 已有
testImplementation("androidx.room:room-testing:2.6.1")
testImplementation("org.jetbrains.kotlinx:kotlinx-coroutines-test:1.7.3")
```

### 4.2 最简单的选择：测纯逻辑

不需要 Android 环境，跑得快：

`app/src/test/java/com/example/todo_list/TaskTest.kt`：

```kotlin
package com.example.todo_list

import com.example.todo_list.data.Task
import org.junit.Assert.*
import org.junit.Test

class TaskTest {

    @Test
    fun `copy 修改完成状态时保留其他字段`() {
        val original = Task(
            id = 1,
            title = "测试任务",
            description = "描述",
            isCompleted = false
        )

        val completed = original.copy(isCompleted = true)

        assertEquals(true, completed.isCompleted)
        assertEquals("测试任务", completed.title)      // 其他字段不变
        assertEquals("描述", completed.description)
        assertEquals(1L, completed.id)
    }

    @Test
    fun `默认值为空描述且未完成`() {
        val task = Task(title = "只填标题")

        assertEquals("", task.description)
        assertEquals(false, task.isCompleted)
    }
}
```

跑法：右键测试类 → Run，或 `./gradlew test`。

**这就满足"至少一个可运行的测试"了。**

### 4.3 想加分：测 Dao

`app/src/androidTest/java/.../TaskDaoTest.kt`：

```kotlin
@RunWith(AndroidJUnit4::class)
class TaskDaoTest {

    private lateinit var db: AppDatabase
    private lateinit var dao: TaskDao

    @Before
    fun setup() {
        val context = ApplicationProvider.getApplicationContext<Context>()
        db = Room.inMemoryDatabaseBuilder(context, AppDatabase::class.java)
            .allowMainThreadQueries()    // 测试环境允许主线程
            .build()
        dao = db.taskDao()
    }

    @After
    fun teardown() = db.close()

    @Test
    fun insertAndGet() = runBlocking {
        val task = Task(title = "测试")
        val id = dao.insertTask(task)
        val retrieved = dao.getTaskById(id)

        assertNotNull(retrieved)
        assertEquals("测试", retrieved?.title)
    }
}
```

⚠️ `inMemoryDatabaseBuilder` 建的是**内存数据库**，跑完即毁，不污染真实数据。

## 五、ContentProvider（4 分，可选）

工作量最大，**建议最后有余力再做**。

### 5.1 建 Provider

```kotlin
class TaskProvider : ContentProvider() {

    companion object {
        const val AUTHORITY = "com.example.todo_list.provider"
        val URI_TASKS = Uri.parse("content://$AUTHORITY/tasks")
    }

    private lateinit var dao: TaskDao

    override fun onCreate(): Boolean {
        dao = AppDatabase.getInstance(context!!).taskDao()
        return true
    }

    override fun query(uri: Uri, projection: Array<out String>?, selection: String?,
                       selectionArgs: Array<out String>?, sortOrder: String?): Cursor? {
        // 用 MatrixCursor 把 List<Task> 包装成 Cursor
        val cursor = MatrixCursor(arrayOf("id", "title", "description", "isCompleted"))
        // 同步查一次（Provider 不在主线程，且需同步返回）
        val tasks = runBlocking { dao.getAllTasks().first() }
        tasks.forEach {
            cursor.addRow(arrayOf(it.id, it.title, it.description, if (it.isCompleted) 1 else 0))
        }
        return cursor
    }

    override fun insert(uri: Uri, values: ContentValues?): Uri? { /* ... */ }
    override fun delete(uri: Uri, selection: String?, selectionArgs: Array<out String>?): Int { /* ... */ }
    override fun update(uri: Uri, values: ContentValues?, selection: String?,
                        selectionArgs: Array<out String>?): Int { /* ... */ }

    override fun getType(uri: Uri): String = "vnd.android.cursor.dir/vnd.$AUTHORITY.tasks"
}
```

⚠️ **ContentProvider 的 `query` 必须同步返回 Cursor**，但你的 Dao 返回 Flow。要用 `runBlocking { flow.first() }` 取一次快照——这是 Provider 里的特例，和"数据库不能在协程外调用"不冲突。

### 5.2 Manifest 注册

```xml
<provider
    android:name=".provider.TaskProvider"
    android:authorities="com.example.todo_list.provider"
    android:exported="true" />
```

⚠️ ContentProvider 要能被其他 App 访问，`exported` 通常是 `true`。

### 5.3 ContentObserver（1 分）

在列表页注册，监听数据变化：

```kotlin
private val observer = object : ContentObserver(Handler(Looper.getMainLooper())) {
    override fun onChange(selfChange: Boolean) {
        // 数据变了，刷新
    }
}

override fun onStart() {
    super.onStart()
    requireContext().contentResolver
        .registerContentObserver(TaskProvider.URI_TASKS, true, observer)
}

override fun onStop() {
    super.onStop()
    requireContext().contentResolver.unregisterContentObserver(observer)
}
```

⚠️ 和广播一样，**注册就要记得注销**。

同时 Provider 里数据变化时要通知：

```kotlin
context.contentResolver.notifyChange(uri, null)
```
