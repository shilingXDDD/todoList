## 一、页面地图

### 1.1 页面层级

```
MainActivity（外壳，唯一）
│   职责：装 BottomNavigationView + Fragment 容器 + 侧边栏容器
│   本身不显示任务数据，不碰数据库
│
├── TaskListFragment            ← 底部导航「任务」    【主页，App 启动默认】
│   └── 点击某项 → TaskDetailActivity
│   └── 点 FAB   → TaskEditActivity（新增）
│
├── SettingsFragment            ← 底部导航「设置」
│   └── 昵称输入（SharedPreferences）
│   └── 深色模式开关（附加）
│   └── 统计入口（附加）
│
└── [侧边栏 Drawer]             ← 可选，分类筛选入口（见 1.3）

详情页与编辑页是独立 Activity，浮在 MainActivity 之上：

TaskDetailActivity    ← 查看单条任务
    └── 编辑 → TaskEditActivity（编辑）
    └── 删除 → AlertDialog 确认

TaskEditActivity      ← 新增 / 编辑共用
    └── 保存 → finish() 回到来源页
```

### 1.2 页面与容器对应关系

| 页面 | 类型 | 布局文件 | 归属容器 | 是否全屏 |
|---|---|---|---|---|
| `MainActivity` | Activity | `activity_main.xml` | — | 是 |
| `TaskListFragment` | Fragment | `fragment_task_list.xml` | `fragmentContainer` | 否（在壳内） |
| `SettingsFragment` | Fragment | `fragment_settings.xml` | `fragmentContainer` | 否（在壳内） |
| `TaskDetailActivity` | Activity | `activity_task_detail.xml` | — | 是 |
| `TaskEditActivity` | Activity | `activity_task_edit.xml` | — | 是 |
| 统计页（附加） | Activity | `activity_statistics.xml` | — | 是 |

### 1.3 ⚠️ 一个需要你拍板的冲突

滴答清单真实形态是**侧边栏（DrawerLayout）**，但评分表明确要求 **BottomNavigationView**（对应"BottomNavigationView 导航"3 分）。

| 方案 | 说明 | 评价 |
|---|---|---|
| A. 只做 BottomNavigationView | 严格按评分表 | 保分，但不像滴答清单 |
| B. 只做侧边栏 | 像滴答清单 | **丢 3 分**，不建议 |
| **C. 两者都做（推荐）** | 底部导航管「任务/设置」两大页；侧边栏管「分类筛选」（今天/收集箱/自定义清单） | 既保分又还原形态 |

**建议选 C**：你的 `activity_main.xml` 本来就是 `DrawerLayout` 根布局，外壳已经预留好了。底部导航负责拿分，侧边栏负责"像滴答清单"，两者职责不冲突（一个是**页面切换**，一个是**数据筛选**）。

侧边栏属于加分项，可放在所有必做功能完成后再做，不影响评分。

## 二、页面详解

### 2.1 MainActivity（外壳）

| 项 | 内容 |
|---|---|
| 布局根 | `DrawerLayout` |
| 子结构 | `MaterialToolbar` + `FragmentContainerView` + `BottomNavigationView` + 侧边栏 `NavigationView` |
| 数据 | **无**（不持有任何任务数据） |
| 职责 | ① 首次启动装载 `TaskListFragment` ② 底部导航切换 Fragment ③ 侧边栏开关（可选） |

**关键约束**：

```kotlin
// 转屏重建时 FragmentManager 会自动恢复 Fragment，不能重复添加
if (savedInstanceState == null) {
    supportFragmentManager.beginTransaction()
        .replace(R.id.fragmentContainer, TaskListFragment())
        .commit()
}
```

**Fragment 切换必须用 `show/hide` 而不是 `replace`**：

| 方式 | 后果 |
|---|---|
| `replace` | 每次切换都销毁重建 → 列表重加载、滚动位置丢失、切回来会闪 |
| `show/hide` | Fragment 实例保留 → 切换顺滑、状态不丢（**推荐**） |

```kotlin
private fun switchTo(target: Fragment) {
    val transaction = supportFragmentManager.beginTransaction()
    supportFragmentManager.fragments.forEach { transaction.hide(it) }
    if (target.isAdded) transaction.show(target)
    else transaction.add(R.id.fragmentContainer, target, target.javaClass.simpleName)
    transaction.commit()
}
```

### 2.4 TaskEditActivity（新增 / 编辑页，共用）

| 项 | 内容 |
|---|---|
| 入参 | `task_id: Long`，**不传 = 新增** |
| 控件 | `TextInputLayout`×2（标题、描述）、`CheckBox`（完成）、`Button`（保存）、日期时间选择（附加）、优先级（附加）、分类（附加） |
| 出口 | 保存 → `finish()`；返回键 → `finish()` |

**两种模式由同一个 `taskId` 区分**：

```kotlin
taskId = intent.getLongExtra(EXTRA_TASK_ID, NO_TASK_ID)   // 默认 -1L
if (taskId != NO_TASK_ID) setupEditMode() else setupCreateMode()
```

| 模式 | 标题栏 | 输入框 | 保存动作 |
|---|---|---|---|
| 新增 | "新建任务" | 空 | `addTask()` |
| 编辑 | "编辑任务" | 回填原值 | `updateTask()` |

### 2.5 SettingsFragment（设置页）

| 项 | 内容 |
|---|---|
| 控件 | 昵称 `EditText` + 保存 `Button`、`Switch`（深色模式，附加）、统计入口 `Button`（附加）、版本号 `TextView` |
| 存储 | `SharedPreferences`（文件名建议 `app_settings`） |

**SharedPreferences 三件事**：

```kotlin
val sp = requireContext().getSharedPreferences("app_settings", MODE_PRIVATE)

// 写
sp.edit().putString(KEY_NICKNAME, name).apply()

// 读（带默认值）
val name = sp.getString(KEY_NICKNAME, "") ?: ""
```

⚠️ **`apply()` 是异步落盘、`commit()` 是同步**。保存后立刻读要用 `commit()`，或者先更新 UI 不从 SP 读。默认用 `apply()`。

---

### 2.6 统计页（附加，3 分）

独立 Activity。三个 `TextView` 显示：总任务数、已完成数、未完成数（或完成率）。

数据来自 Dao 的 `COUNT` 查询：

```kotlin
@Query("SELECT COUNT(*) FROM tasks") fun countAll(): Flow<Int>
@Query("SELECT COUNT(*) FROM tasks WHERE isCompleted = 1") fun countCompleted(): Flow<Int>
```

⚠️ 评分表要求"**数据必须准确**"。用 `Flow` 保证和列表实时一致，不要用一次性的 `suspend` 查询（那样打开统计页时数据是旧的）。

### 4.2 Service 要点

```kotlin
class TaskSyncService : Service() {
    override fun onStartCommand(intent: Intent?, flags: Int, startId: Int): Int {
        Thread {
            Thread.sleep(2000)                        // 模拟耗时，必须在子线程
            sendBroadcast(Intent(ACTION_SYNC_FINISHED).setPackage(packageName))
            stopSelf()                                // 自己结束
        }.start()
        return START_NOT_STICKY
    }
    override fun onBind(intent: Intent?): IBinder? = null
}
```

| 要求 | 做法 | 分值 |
|---|---|---|
| 点击可启动 | `startService(Intent(this, TaskSyncService::class.java))` | 1 |
| 模拟约 2 秒 | `Thread.sleep(2000)` | 2 |
| 完成后 `stopSelf()` | 子线程末尾调用 | 1 |
| 不直接操作 View | 用广播通知页面 | 1 |

⚠️ `Thread.sleep` 必须在子线程，放主线程直接 ANR。

### 4.3 BroadcastReceiver 要点

**同步完成广播**（动态注册，推荐）：

```kotlin
// Fragment.onStart()
context.registerReceiver(
    syncReceiver,
    IntentFilter(ACTION_SYNC_FINISHED),
    Context.RECEIVER_NOT_EXPORTED        // ⚠️ Android 13+ 必填
)

// Fragment.onStop()
context.unregisterReceiver(syncReceiver)
```

⚠️ **两个必踩的坑（你 targetSdk = 34）**：

1. 动态注册**必须**带 `RECEIVER_NOT_EXPORTED` 或 `RECEIVER_EXPORTED`，否则直接崩溃。
2. 记得在 `onStop` 注销，否则报 `IntentReceiverLeaked`。

**"处理重复同步"1 分的做法**：

```kotlin
private var isSyncing = false

fun startSync() {
    if (isSyncing) return          // 同步中再点直接忽略
    isSyncing = true
    startService(...)
}
// 收到广播后置回 false
```

### 4.4 通知要点（5 分）

```kotlin
// 1. 创建渠道（Android 8.0+ 必须）
val channel = NotificationChannel(CHANNEL_ID, "任务提醒", NotificationManager.IMPORTANCE_HIGH)
manager.createNotificationChannel(channel)

// 2. PendingIntent（点通知进详情页）
val intent = Intent(context, TaskDetailActivity::class.java)
    .putExtra("task_id", taskId)
val pi = PendingIntent.getActivity(
    context, taskId.toInt(), intent,
    PendingIntent.FLAG_UPDATE_CURRENT or PendingIntent.FLAG_IMMUTABLE   // ⚠️ Android 12+ 必填
)

// 3. 发通知
NotificationCompat.Builder(context, CHANNEL_ID)
    .setSmallIcon(R.drawable.ic_launcher_foreground)
    .setContentTitle(task.title)
    .setContentText(task.description)
    .setContentIntent(pi)
    .setAutoCancel(true)
    .build()
```

| 考点 | 分值 | 易错点 |
|---|---|---|
| 创建通知渠道 | 1 | 渠道 ID 要用常量，别每次随机生成 |
| 成功显示通知 | 1 | **Android 13+ 需要运行时权限** |
| 处理通知权限 | 1 | `POST_NOTIFICATIONS` |
| 通知含任务信息 | 1 | 标题/描述要真取出来 |
| 点击进对应详情页 | 1 | `requestCode` 用 `taskId`，避免互相覆盖 |

⚠️ **Android 13+ 权限（最容易丢的 2 分）**：

```xml
<uses-permission android:name="android.permission.POST_NOTIFICATIONS" />
```

```kotlin
if (Build.VERSION.SDK_INT >= 33) {
    registerForActivityResult(ActivityResultContracts.RequestPermission()) { }
        .launch(Manifest.permission.POST_NOTIFICATIONS)
}
```

不申请的话在 Android 13+ 设备上通知**完全不显示**。

## 五、数据模型

### 5.1 Task 实体

**第一步（内存版）**：

```kotlin
data class Task(
    val id: Long = 0,
    val title: String,
    val description: String = "",
    val isCompleted: Boolean = false
)
```

**第二步（Room 版，只加注解不改结构）**：

```kotlin
@Entity(tableName = "tasks")
data class Task(
    @PrimaryKey(autoGenerate = true) val id: Long = 0,
    val title: String,
    val description: String = "",
    val isCompleted: Boolean = false
)
```

**加附加字段后的最终形态**（建议一次到位，全部给默认值）：

| 字段 | 类型 | 用途 | 附加分 |
|---|---|---|---|
| `id` | `Long` | 主键，自增 | — |
| `title` | `String` | 标题 | — |
| `description` | `String` | 描述 | — |
| `isCompleted` | `Boolean` | 完成状态 | — |
| `category` | `String` | 分类（学习/工作/生活） | 2 |
| `priority` | `Int` | 优先级 0~3 | 2 |
| `dueDate` | `Long?` | 截止时间戳 | 2 |
| `reminderTime` | `Long?` | 提醒时间戳 | 2 |
| `note` | `String` | 备注 | 2 |
| `link` | `String` | 学习资料链接 | 2 |
| `createdAt` | `Long` | 创建时间（排序用） | — |

### 5.2 Dao

```kotlin
@Dao
interface TaskDao {
    @Query("SELECT * FROM tasks ORDER BY id DESC")
    fun getAllTasks(): Flow<List<Task>>                    // Flow 是自动刷新的关键

    @Query("SELECT * FROM tasks WHERE id = :id")
    suspend fun getTaskById(id: Long): Task?               // 返回可空，调用方必须判空

    @Insert suspend fun insertTask(task: Task): Long
    @Update suspend fun updateTask(task: Task)
    @Delete suspend fun deleteTask(task: Task)

    // 附加
    @Query("SELECT * FROM tasks WHERE title LIKE '%' || :kw || '%'")
    fun searchTasks(kw: String): Flow<List<Task>>

    @Query("SELECT COUNT(*) FROM tasks")
    fun countAll(): Flow<Int>

    @Query("SELECT COUNT(*) FROM tasks WHERE isCompleted = 1")
    fun countCompleted(): Flow<Int>
}
```

⚠️ **绝对不要写 `runBlocking { dao.xxx() }`** —— 在主线程做数据库操作，轻则卡顿，重则崩溃，还会丢掉"后台线程"那 1 分。

### 5.3 为什么用 `val` 而不是 `var`

改状态用 `copy()` 生成新对象：

```kotlin
TaskRepository.updateTask(task.copy(isCompleted = true))
```

DiffUtil 靠 `equals` 比较新旧对象。如果直接改原对象字段，新旧是**同一个引用**，DiffUtil 判断"没变化"，界面就不刷新。这是"数据改了但界面不动"的头号原因。

## 六、核心逻辑拆解

### 6.1 新增任务

```
[列表页] 点 FAB
   ↓ Intent 不携带 task_id
[编辑页] onCreate → getLongExtra(默认 -1) → taskId == -1 → 新建模式
   ↓ 标题栏显示"新建任务"，输入框为空
[用户] 输入内容，点保存
   ↓ saveTask()
   ↓ title.trim() 为空？
      ├─ 是 → titleInputLayout.error = "标题不能为空"，return（不保存不返回）
      └─ 否 → 继续
   ↓ TaskRepository.addTask(Task(title, desc, isCompleted))
   ↓ Toast "保存成功"
   ↓ finish()
[列表页] onResume() 触发 → 重新取数据 → 新任务出现在最上面 ✅
```

### 6.2 编辑任务

```
[列表页] 点某一行
   ↓ TaskAdapter.onItemClick(task)
   ↓ Intent.putExtra("task_id", task.id)
[编辑页] getLongExtra 拿到真实 ID → 编辑模式
   ↓ getTaskById(id) 查出任务
   ↓ 判空：null → Toast 提示 + finish()
   ↓ setText 回填标题/描述/完成状态
[用户] 修改后点保存
   ↓ 校验 → updateTask(Task(id, ...))
   ↓ finish()
[列表页] onResume → 显示新内容 ✅
```

### 6.3 删除任务

```
[详情页] 点删除按钮
   ↓ AlertDialog.Builder
      .setTitle("确认删除")
      .setMessage("删除后不可恢复")
      .setNegativeButton("取消") { dialog, _ -> dialog.dismiss() }   ← 取消只 dismiss
      .setPositiveButton("删除") { _, _ -> doDelete() }
      .show()
   ↓ doDelete():
      ├─ repository.deleteTask(task)
      ├─ cancelReminder(task.id)      ← 附加：同步取消 Alarm
      ├─ Toast "已删除"
      └─ finish()
```

⚠️ **删除时取消提醒（附加 2 分）**：只删数据库不取消 Alarm，到点会弹出通知，点进去任务已不存在 → 崩溃。

```kotlin
val am = getSystemService(AlarmManager::class.java)
am.cancel(pendingIntentFor(taskId))
```

### 6.4 完成状态切换

```
[列表] 勾选 CheckBox
   ↓ TaskAdapter.onCheckedChange(task, isChecked)
   ↓ updateTask(task.copy(isCompleted = isChecked))
   ↓ 重新加载 → 该行标题加中划线
   ↓ 详情页也重新读库 → 两处状态一致 ✅（1 分）
```

⚠️ **CheckBox 三行固定写法**（防复用串位）：

```kotlin
holder.binding.completedCheckBox.setOnCheckedChangeListener(null)   // 1. 清空
holder.binding.completedCheckBox.isChecked = task.isCompleted        // 2. 设值
holder.binding.completedCheckBox.setOnCheckedChangeListener { _, b -> // 3. 新监听
    onCheckedChange(task, b)
}
```

顺序错了，滚动时勾选状态会串到别的行。

### 6.5 同步流程（Service ↔ 广播）

```
[列表页] 点"同步"按钮
   ↓ if (isSyncing) return            ← 防重复点击（1 分）
   ↓ isSyncing = true
   ↓ startService(TaskSyncService)
[Service] onStartCommand
   ↓ 启子线程 → Thread.sleep(2000)
   ↓ sendBroadcast(ACTION_SYNC_FINISHED) + setPackage(packageName)
   ↓ stopSelf()                       ← 必须自己结束（1 分）
[列表页] 动态注册的 Receiver 收到广播
   ↓ Toast "同步完成"                  ← 1 分
   ↓ isSyncing = false
```

⚠️ **Android 8.0+ 对隐式广播有限制**，发送时必须 `setPackage(packageName)` 变成显式广播，否则收不到。

### 6.6 提醒流程（AlarmManager ↔ Receiver ↔ 通知）

```
[详情/编辑页] 设置提醒时间（附加）
   ↓ DatePickerDialog + TimePickerDialog 选时间
   ↓ 存入 task.reminderTime
   ↓ AlarmManager.setExact(...) 注册 PendingIntent（带 task_id）
   
[到点] AlarmManager 触发
   ↓ TaskReceiver.onReceive()
   ↓ 从 Intent 取 task_id → 查库拿任务
   ↓ 创建通知渠道 → 构建通知 → notify()
   ↓ ⚠️ onReceive 不能做耗时操作（超过 10 秒 ANR）
   
[用户] 点通知
   ↓ PendingIntent 打开 TaskDetailActivity
   ↓ task_id 传进去 → 显示对应任务 ✅（1 分）
```

### 6.7 返回刷新（3 分，最易丢）

三种做法：

| 方案 | 适用 | 评价 |
|---|---|---|
| `onResume()` 里重新查 | 第一步（内存数据） | 简单可靠，保底 |
| `Flow` 自动推送 | 第二步（Room） | 最优雅，推荐 |
| `ActivityResultLauncher` | 备选 | 需注册，稍麻烦 |

⚠️ 用 `Flow` 时统一这样收集，避免"重复收集导致数据翻倍"：

```kotlin
viewLifecycleOwner.lifecycleScope.launch {
    repeatOnLifecycle(Lifecycle.State.STARTED) {
        viewModel.tasks.collect { adapter.submitList(it) }
    }
}
```

### 6.8 搜索（附加 2 分）

```
SearchView 输入 → setOnQueryTextListener
   ↓ 关键字传给 Dao：WHERE title LIKE '%' || :kw || '%'
   ↓ Flow 返回新列表 → submitList
   ↓ 结果为空 → 显示"未找到匹配任务"   ← 评分表特别要求
```

### 6.9 横竖屏恢复（附加 2 分）

`TaskEditActivity` 里用户填了一半标题，转屏后必须还在：

| 方案 | 说明 |
|---|---|
| 给 EditText 加 `android:id` | 系统自动保存恢复（**最低成本**） |
| `onSaveInstanceState` | 手动存 |
| `ViewModel` 持有 | 推荐，顺带拿 ViewModel 那 2 分 |

Activity 端还要防止 Fragment 重复添加（见 2.1）。

### 6.10 深色模式（附加 2 分）

- 你当前主题 `Theme.Material3.DayNight.NoActionBar` 已支持跟随系统
- 颜色**必须走 `colors.xml` + `values-night/colors.xml`**，不能硬编码 `#FFFFFF`
- 文字用 `?attr/colorOnSurface`、背景用 `?attr/colorSurface`
- 手动切换用 `AppCompatDelegate.setDefaultNightMode(MODE_NIGHT_YES/NO)`

## 七、状态流转

### 7.1 任务状态机

```
                  新增
                   ↓
            ┌─────────────┐
            │   未完成     │ ←──────────┐
            │ isCompleted │            │ 取消完成
            │    = false  │            │
            └──────┬──────┘            │
                   │ 勾选               │
                   ↓                   │
            ┌─────────────┐  ──────────┘
            │   已完成     │
            │ isCompleted │
            │    = true   │
            └──────┬──────┘
                   │ 删除
                   ↓
              （数据移除 + 取消提醒）
```

状态变更必须**落库**，不能只改内存，否则详情页和列表页不一致。

### 7.2 页面生命周期关键节点

| 时机 | 做什么 | 不做什么 |
|---|---|---|
| `Activity.onCreate` | inflate binding、setContentView | 不要在这里查数据库（可能耗时） |
| `Fragment.onCreateView` | 只 inflate 布局并返回 View | **不要碰数据、不要设监听** |
| `Fragment.onViewCreated` | 绑 View、设监听、创建 Adapter | — |
| `Fragment.onStart` | 动态注册 Receiver | — |
| `Fragment.onResume` | 重新加载数据（第一步方案） | — |
| `Fragment.onStop` | **注销 Receiver** | 忘了会 `IntentReceiverLeaked` |
| `Fragment.onDestroyView` | **`_binding = null`** | 忘了会内存泄漏 |
| `Activity.onSaveInstanceState` | 存临时输入 | — |

这三条做到，"项目结构"2 分和 "Activity 职责清晰"3 分就稳了。
