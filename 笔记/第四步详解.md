## 二、准备：给 Task 加字段

所有附加功能都依赖新字段。一次性加齐，避免反复改数据库版本。

```kotlin
@Entity(tableName = "tasks")
data class Task(
    @PrimaryKey(autoGenerate = true)
    val id: Long = 0,

    val title: String,
    val description: String = "",
    val isCompleted: Boolean = false,

    // ↓↓↓ 附加字段，全部给默认值 ↓↓↓
    val category: String = "默认",      // 分类
    val priority: Int = 0,             // 优先级 0无 1低 2中 3高
    val dueDate: Long? = null,         // 截止时间戳
    val reminderTime: Long? = null,    // 提醒时间戳
    val note: String = "",             // 备注
    val link: String = "",             // 学习资料链接
    val createdAt: Long = System.currentTimeMillis()
)
```

⚠️ **加字段必须同时做两件事**：

**① 数据库版本 +1**

```kotlin
@Database(entities = [Task::class], version = 2, exportSchema = false)
```

**② 提供迁移，否则老数据崩溃**

```kotlin
val MIGRATION_1_2 = object : Migration(1, 2) {
    override fun migrate(db: SupportSQLiteDatabase) {
        db.execSQL("ALTER TABLE tasks ADD COLUMN category TEXT NOT NULL DEFAULT '默认'")
        db.execSQL("ALTER TABLE tasks ADD COLUMN priority INTEGER NOT NULL DEFAULT 0")
        db.execSQL("ALTER TABLE tasks ADD COLUMN dueDate INTEGER")
        db.execSQL("ALTER TABLE tasks ADD COLUMN reminderTime INTEGER")
        db.execSQL("ALTER TABLE tasks ADD COLUMN note TEXT NOT NULL DEFAULT ''")
        db.execSQL("ALTER TABLE tasks ADD COLUMN link TEXT NOT NULL DEFAULT ''")
        db.execSQL("ALTER TABLE tasks ADD COLUMN createdAt INTEGER NOT NULL DEFAULT 0")
    }
}
```

注册到 builder：

```kotlin
Room.databaseBuilder(context, AppDatabase::class.java, "todo_database")
    .addMigrations(MIGRATION_1_2)
    .build()
```

⚠️ 开发阶段不想写迁移，可以用 `fallbackToDestructiveMigration()`——它会**清空数据重建表**。仅限开发期，答辩前要去掉，否则"数据持久化"那 3 分会被质疑。

## 三、统计页面（3 分，性价比最高）⭐

独立 Activity，三个 `TextView` 就够。

### 3.1 Dao 加查询

```kotlin
@Query("SELECT COUNT(*) FROM tasks")
fun countAll(): Flow<Int>

@Query("SELECT COUNT(*) FROM tasks WHERE isCompleted = 1")
fun countCompleted(): Flow<Int>
```

⚠️ 用 `Flow` 不用 `suspend`。评分表要求「**数据必须准确**」——用一次性查询，打开页面时数据是旧的；用 Flow 才和列表实时一致。

注意 `WHERE isCompleted = 1`：SQLite 里 Boolean 存成 0/1，不能写 `= true`。

### 3.2 布局

```xml
<LinearLayout ... android:padding="24dp" android:orientation="vertical">

    <TextView android:id="@+id/txv_total" ... />
    <TextView android:id="@+id/txv_completed" ... />
    <TextView android:id="@+id/txv_pending" ... />
    <TextView android:id="@+id/txv_rate" ... />    <!-- 完成率 -->

</LinearLayout>
```

### 3.3 代码要点

```kotlin
lifecycleScope.launch {
    repeatOnLifecycle(Lifecycle.State.STARTED) {
        launch { repository.countAll().collect { ... } }
        launch { repository.countCompleted().collect { ... } }
    }
}
```

完成率 = 已完成 ÷ 总数 × 100，**注意除数是 0 时要判断**（否则显示 `NaN`）。

### 3.4 入口

在 `SettingsFragment` 加个按钮跳过去（`settings_placeholder` 那个位置正好可以放）。

## 四、搜索任务（2 分）⭐

### 4.1 Dao

```kotlin
@Query("SELECT * FROM tasks WHERE title LIKE '%' || :keyword || '%' ORDER BY id DESC")
fun searchTasks(keyword: String): Flow<List<Task>>
```

`'%' || :keyword || '%'` 是 SQLite 的字符串拼接写法，等于模糊匹配。

### 4.2 列表页加 SearchView

`fragment_task_list.xml` 顶部加：

```xml
<SearchView
    android:id="@+id/searchView"
    android:layout_width="match_parent"
    android:layout_height="wrap_content"
    android:queryHint="@string/hint_search" />
```

⚠️ `SearchView` 是平台控件（`android.widget.SearchView`），不需要 Material。

### 4.3 逻辑：关键词为空时显示全部

```kotlin
private var keyword = ""

private fun observeTasks() {
    viewLifecycleOwner.lifecycleScope.launch {
        repeatOnLifecycle(Lifecycle.State.STARTED) {
            TaskRepository.getTasks().collect { allTasks ->
                val filtered = if (keyword.isBlank()) allTasks
                              else allTasks.filter { it.title.contains(keyword, true) }
                taskAdapter.submitList(filtered)

                // ⚠️ 评分表特别要求：无结果要有明确提示
                binding.emptyTextView.visibility =
                    if (filtered.isEmpty()) View.VISIBLE else View.GONE
                binding.emptyTextView.text =
                    if (keyword.isBlank()) getString(R.string.empty_task_list)
                    else getString(R.string.empty_search_result)
            }
        }
    }
}
```

**这里用「在内存里过滤」而不是查数据库**，好处是逻辑简单、不用切换数据源。任务量小时（课设级别）完全够用。

如果想用 Dao 的 `searchTasks` 查，需要切换 Flow 源，代码复杂些，可酌情选择。

**⚠️ 别忘了那条 1 分**：`empty_search_result` 文案必须有（"未找到匹配的任务"）。

## 七、筛选或排序（2 分，二选一即可）

评分表写的是「**或**」，所以做一样就够。

**排序更省事**——在 Dao 里换 `ORDER BY`：

```kotlin
// 按创建时间倒序（最新的在前）
@Query("SELECT * FROM tasks ORDER BY createdAt DESC")
fun getAllTasksSortedByTime(): Flow<List<Task>>

// 按优先级
@Query("SELECT * FROM tasks ORDER BY priority DESC, id DESC")
fun getAllTasksSortedByPriority(): Flow<List<Task>>
```

配合设置页的开关，或者列表页的一个排序按钮切换。

**筛选**示例（只看未完成）：

```kotlin
@Query("SELECT * FROM tasks WHERE isCompleted = 0 ORDER BY id DESC")

```

## 八、日期时间设置（2 分）

用两个系统对话框：`DatePickerDialog` + `TimePickerDialog`。

### 8.1 编辑页加个按钮

```xml
<Button
    android:id="@+id/btn_pick_datetime"
    android:layout_width="match_parent"
    android:layout_height="wrap_content"
    android:text="设置截止日期" />
```

### 8.2 逻辑

```kotlin
private var selectedDueDate: Long? = null

private fun showDateTimePicker() {
    val calendar = Calendar.getInstance()

    DatePickerDialog(this, { _, year, month, day ->
        TimePickerDialog(this, { _, hour, minute ->
            val cal = Calendar.getInstance().apply {
                set(year, month, day, hour, minute, 0)
                set(Calendar.MILLISECOND, 0)
            }
            selectedDueDate = cal.timeInMillis
            binding.btnPickDatetime.text = formatDateTime(cal.timeInMillis)
        }, calendar.get(Calendar.HOUR_OF_DAY), calendar.get(Calendar.MINUTE), true).show()

    }, calendar.get(Calendar.YEAR), calendar.get(Calendar.MONTH),
       calendar.get(Calendar.DAY_OF_MONTH)).show()
}
```

⚠️ **一定要 `set(Calendar.MILLISECOND, 0)`**。不清零的话，同一天同一时刻的两个任务时间戳不同，按时间排序或判断"是不是今天"会出错。

### 8.3 展示

详情页或列表项显示格式化后的日期。`util/TimeUtil.kt` 正好派上用场：

```kotlin
object TimeUtil {
    private val formatter = SimpleDateFormat("yyyy-MM-dd HH:mm", Locale.getDefault())
    fun format(timestamp: Long): String = formatter.format(Date(timestamp))
}
```

## 十、AlarmManager 提醒与取消（4 分，工作量最大）

⚠️ **建议最后做**，依赖多、坑多。

### 10.1 注册提醒

```kotlin
private fun setReminder(taskId: Long, timeMillis: Long, title: String) {
    val alarmManager = getSystemService(AlarmManager::class.java)

    val intent = Intent(this, TaskReceiver::class.java).apply {
        action = TaskReceiver.ACTION_TASK_REMIND
        putExtra(TaskReceiver.EXTRA_TASK_ID, taskId)
        putExtra(TaskReceiver.EXTRA_TASK_TITLE, title)
    }
    val pi = PendingIntent.getBroadcast(
        this, taskId.toInt(), intent,
        PendingIntent.FLAG_UPDATE_CURRENT or PendingIntent.FLAG_IMMUTABLE
    )

    alarmManager.setExactAndAllowWhileIdle(AlarmManager.RTC_WAKEUP, timeMillis, pi)
}
```

⚠️ 注意这里是 **`getBroadcast`**（不是 `getActivity`），因为目标是 Receiver。

⚠️ Android 12+ 用 `setExact` 需要 `SCHEDULE_EXACT_ALARM` 权限，且该权限**默认关闭**，需要跳设置页让用户开。课设阶段建议用 `setWindow()` 或 `set()` 规避，或者引导用户手动授权。

### 10.2 删除时取消提醒（2 分，必拿）

⚠️ **这 2 分最容易被忽略，也最容易在答辩演示时翻车**：

只删数据库不取消 Alarm → 到点弹出通知 → 用户点进去 → 任务已不存在 → **崩溃**。

```kotlin
private fun cancelReminder(taskId: Long) {
    val alarmManager = getSystemService(AlarmManager::class.java)
    val intent = Intent(this, TaskReceiver::class.java).apply {
        action = TaskReceiver.ACTION_TASK_REMIND
    }
    val pi = PendingIntent.getBroadcast(
        this, taskId.toInt(), intent,
        PendingIntent.FLAG_UPDATE_CURRENT or PendingIntent.FLAG_IMMUTABLE
    )
    alarmManager.cancel(pi)     // ← 关键
    pi.cancel()
}
```

**取消用的 Intent 必须和注册时"匹配"**：相同的 action、相同的 requestCode。Kotlin 里 `Intent` 的 extra 不参与匹配，所以只放 action 也能取消掉。

在删除确认的 `PositiveButton` 里调用：

```kotlin
lifecycleScope.launch {
    TaskRepository.deleteTask(current)
    cancelReminder(current.id)      // ⚠️ 别漏
    finish()
}
```

## 十二、常见错误

| 现象 | 原因 | 解决 |
|---|---|---|
| 加字段后 App 崩溃 | 没 `version + 1` 或没写迁移 | 见第二节 |
| 统计数永远是 0 | `WHERE isCompleted = true` | SQLite 要用 `= 1` |
| 完成率显示 `NaN` | 除数为 0 | 判断总数是否为 0 |
| 搜索无结果但没提示 | 忘了改空状态文案 | 加 `empty_search_result` |
| 同日期任务排序错乱 | 毫秒没清零 | `set(Calendar.MILLISECOND, 0)` |
| 删了任务还收到通知 | 没取消 Alarm | `alarmManager.cancel(pi)` |
| PendingIntent 崩溃 | 缺 `FLAG_IMMUTABLE` | 补上 |
| `Uri.parse` 崩溃 | 链接没有 http 前缀 | 判断并补全 |
