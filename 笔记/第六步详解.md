## 零、为什么要单独做这一步

评分表 9.3 的评分建议是整个评分体系的"总闸"：

| 完成情况 | 得分上限 |
|---|---|
| 仅完成界面或字段设计，核心逻辑未完成 | **30%** |
| 页面完成，但数据无法保存或功能无法正常运行 | **50%** |
| 功能基本可用，但存在少量问题 | 70%~90% |
| 功能完整、数据正确、可稳定演示 | **100%** |

**"可稳定演示"这五个字值一半的分。** 你把功能都写了但演示时崩一次，可能直接从 100% 掉到 70%。

这一步要做三件事：
1. **系统自检**（找出会崩的地方）
2. **准备材料**（README、APK、截图、视频）
3. **答辩加固**（预设演示路径，避开雷区）

## 一、系统自检清单

按这个顺序**在真机上逐条走一遍**，不要只在模拟器测。

### 1.1 基础功能（必做 100 分主流程）

**列表与新增**
- [ ] App 启动，列表正常显示
- [ ] 点 FAB 进新增页
- [ ] 标题留空点保存 → 有红色提示，**且不返回**
- [ ] 只输入空格点保存 → 同样被拦
- [ ] 填标题保存 → Toast → 回到列表 → 新任务出现

**详情与编辑**
- [ ] 点列表某项 → 进详情页，信息完整
- [ ] 点编辑 → 输入框**有原内容**
- [ ] 改标题保存 → 回列表显示新标题，**没有多出重复条目**
- [ ] 点删除 → 弹确认框
- [ ] 点取消 → **不删除**
- [ ] 点确定 → 删除成功，列表少一条

**完成状态**
- [ ] 勾选圆形复选框 → 标题加中划线**并置灰**
- [ ] 进详情页 → 状态显示"已完成"（**两处一致**）
- [ ] 来回滚动列表 → 勾选状态**不串到别的行**
- [ ] 点圆形复选框 → **只切换完成态，不会跳进详情页**

**UI 重构后的外观**
- [ ] 全局背景是浅灰白，列表项是白色圆角卡片
- [ ] 底部导航选中蓝、未选中灰
- [ ] 列表滑到底部，最后一条**没有被 FAB 挡住**
- [ ] FAB 是蓝色圆形 + 白色加号
- [ ] 编辑页输入框**没有下划线**（白卡片内的无边框输入）

**空状态**
- [ ] 删光所有任务 → 显示"暂无任务"

### 1.2 数据持久化（核心 3 分）

⚠️ **必须杀进程验证**，按返回键退出不算：

```
1. 新增一条任务「测试持久化」
2. 点 Logcat 旁的红色停止按钮
   （或 adb shell am kill com.example.todo_list）
3. 重新打开 App
4. 任务还在 ✅
```

- [ ] 重启后新增的任务还在
- [ ] 重启后**修改**的内容还在（改标题 → 杀进程 → 是新标题）
- [ ] 重启后完成状态还在

### 1.3 Service 与通知（20 分）

- [ ] 点同步 → 约 2 秒后 Toast
- [ ] **连点两次同步** → 只弹一次（防重复）
- [ ] 切到设置页再切回 → 不崩溃（广播已注销）
- [ ] 首次点测试提醒 → 弹权限申请
- [ ] 授权后通知栏出现通知，标题是任务标题
- [ ] 点通知 → **进对应任务详情页**（不是别的）
- [ ] 拒绝权限 → 有 Toast 提示，不崩溃

### 1.4 设置页（3 分）

- [ ] 输入昵称 → 保存 → Toast → 欢迎语变化
- [ ] 切走再回来 → 昵称还在输入框
- [ ] **杀进程重开** → 昵称还在

### 1.5 边界与异常（3 分）

- [ ] 标题为空被拦下
- [ ] 空列表有提示
- [ ] 通知权限被拒有提示

### 1.6 附加项（做一项勾一项）

- [ ] 统计页数字和列表一致，完成率正确（**已完成，待验证**）
- [ ] 搜索有结果 + 无结果有提示
- [ ] 分类/优先级/日期**能录入、能保存、能显示**（三关全过）
- [ ] **编辑保存后分类/优先级没丢**（第四步 2.6 的 bug 已修）

- [ ] 转屏后输入内容和列表不丢
- [ ] 深色模式三页文字都清晰
- [ ] 至少一个测试能跑通

## 二、常见崩溃点与预防

按"演示时最容易翻车"排序：

| 排名 | 崩溃场景 | 预防 |
|---|---|---|
| 1 | 删除任务后，之前的提醒通知弹出 → 点进去任务不存在 | 删除时 `alarmManager.cancel(pi)` |
| 2 | 快速连点同步 → 多次广播 | `isSyncing` 标志位 |
| 3 | 转屏后 Fragment 叠加，列表变两份 | `savedInstanceState == null` 判断 |
| 4 | 深色模式某处白底白字 | 检查硬编码颜色 |
| 5 | 加了字段但没改数据库版本 | `version + 1` + Migration |
| 6 | 详情页收到非法 ID | `getTaskById` 判空 + `finish()` |
| 7 | 日期筛选器点了没反应 | `ChipGroup` 要用 `setOnCheckedStateChangeListener`，旧的 `setOnCheckedChangeListener` 已废弃 |
| 8 | 已完成的任务还标红 | 过期判断要带 `!task.isCompleted` |
| 9 | **编辑保存后分类/优先级全没了** | `Task(id, ...)` 重建对象丢了字段，改用 `existing.copy(...)`（见第四步 2.6） |
| 10 | 统计页完成率显示 `NaN` | 空列表时除数为 0，要判断 `if (total == 0) 0` |
| 11 | 深色模式某处白底白字 | `values-night/colors.xml` 漏了某个颜色覆盖 |

**建议**：演示前**完整走一遍 1.1~1.5**，每条都能过再录视频。

⚠️ 第 9 条在第四步做完附加字段后**极易出现**：
演示时"编辑任务"是必经操作，一编辑分类优先级就消失，会非常尴尬。
录视频前务必先验证「设置分类 → 编辑改标题 → 保存 → 分类还在」。

### 8.3 可能被追问的问题

提前准备这几个答案：

| 问题 | 要点 |
|---|---|
| 为什么用 Room 不用 SQLiteOpenHelper？ | 编译期 SQL 校验、少写样板代码、原生支持协程和 Flow |
| 为什么数据库操作放子线程？ | 主线程做 IO 会 ANR；Room 会直接抛异常强制约束 |
| Service 和 Thread 的区别？ | Service 是组件，有生命周期，可被系统调度；Thread 只是执行单元 |
| 静态注册和动态注册广播的区别？ | 动态随页面生命周期，8.0+ 不受隐式广播限制；静态常驻但受限 |
| `apply()` 和 `commit()` 的区别？ | apply 异步无返回值；commit 同步返回 Boolean |
| Flow 和 LiveData 的区别？ | Flow 是 Kotlin 协程生态的冷流，操作符丰富；LiveData 生命周期感知但能力有限 |
| 为什么传 ID 不传对象？ | 避免序列化开销；传 ID 拿到的是最新数据而非快照 |
