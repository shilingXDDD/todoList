## 零、先修一个会让功能失效的 Bug

**这不是第二步的内容，但会让你误以为第二步没做对，必须先修。**

`TaskEditActivity.kt` 第 20 行：

```kotlin
fun startUI(context: Context, taskId: Long? = null) {   // ⚠️ 参数类型是 Long?
    val intent = Intent(context, TaskEditActivity::class.java)
    intent.putExtra(EXTRA_TASK_ID, taskId)              // ⚠️ 这里出事了
```

`taskId` 是 **可空的 `Long?`**，而 `putExtra` 没有接收 `Long?` 的重载。Kotlin 会退而求其次，匹配到 `putExtra(String, Serializable)`——因为 `Long` 实现了 `Serializable`。

结果：ID 被当成「可序列化对象」存进去，而读取时用的是：

```kotlin
intent.getLongExtra(EXTRA_TASK_ID, NO_TASK_ID)
```

`getLongExtra` 找的是 `Long` 类型，找不到就返回默认值 `-1`。

**后果**：点「编辑」进入编辑页时，`taskId` 永远是 `-1`，被判成**新增模式**。你改完标题保存，不会更新原任务，而是**新建一条重复任务**。

### 修法

把参数改成非空 `Long`，用 `NO_TASK_ID` 作默认值：

```kotlin
fun startUI(context: Context, taskId: Long = NO_TASK_ID) {   // 去掉 ?
    val intent = Intent(context, TaskEditActivity::class.java)
    intent.putExtra(EXTRA_TASK_ID, taskId)                   // 现在会匹配 putExtra(String, Long)
    context.startActivity(intent)
}
```

这样 `TaskEditActivity.startUI(requireContext())`（列表页新增）走默认值 `-1`，`startUI(this, taskId)`（详情页编辑）传真实 ID，两边都正确。

**验证**：点第 2 条任务 → 编辑 → 改标题 → 保存 → 回列表，应该只有 1 条被改，而不是多出一条。

## 二、Room 是什么

三个角色：

| 角色 | 作用 | 类比 |
|---|---|---|
| **Entity** | 定义一张表的结构 | 表头（有哪些列） |
| **Dao** | 定义能做什么操作 | SQL 语句集合 |
| **Database** | 数据库本身，持有 Dao | 数据库文件 |

再加一个：

| **Repository** | 对上层屏蔽细节 | 你已经有这个文件了 |

**分层的关键收益**：第二步只改 `data/` 包里的文件，上层 `ui/` 的 Fragment、Adapter、Activity **几乎不用动**。这就是当初建 `TaskRepository` 的意义。

## 四、第 2 步：Task 加注解

现在 `Task.kt` 是纯 data class，加两个注解就变成数据库表：

```kotlin
package com.example.todo_list.data

import androidx.room.Entity
import androidx.room.PrimaryKey

@Entity(tableName = "tasks")
data class Task(
    @PrimaryKey(autoGenerate = true)
    val id: Long = 0,

    val title: String,
    val description: String = "",
    val isCompleted: Boolean = false
)
```

| 注解 | 含义 |
|---|---|
| `@Entity(tableName = "tasks")` | 这个类对应一张叫 `tasks` 的表 |
| `@PrimaryKey(autoGenerate = true)` | `id` 是主键，插入时自动生成（不用手动赋值） |

**注意 `id` 默认值是 `0`**：`autoGenerate` 下传 `0` 表示"我没指定，你自动分配"。所以新增时不要手动算 ID。

**结构一个字都不用改**——这就是第一步先用 data class 的好处。

## 五、第 3 步：建 TaskDao

新建 `data/TaskDao.kt`：

```kotlin
package com.example.todo_list.data

import androidx.room.Dao
import androidx.room.Delete
import androidx.room.Insert
import androidx.room.Query
import androidx.room.Update
import kotlinx.coroutines.flow.Flow

@Dao
interface TaskDao {

    // 返回 Flow：数据一变自动推送新列表，UI 跟着刷新
    @Query("SELECT * FROM tasks ORDER BY id DESC")
    fun getAllTasks(): Flow<List<Task>>

    @Query("SELECT * FROM tasks WHERE id = :id")
    suspend fun getTaskById(id: Long): Task?

    @Insert
    suspend fun insertTask(task: Task): Long

    @Update
    suspend fun updateTask(task: Task)

    @Delete
    suspend fun deleteTask(task: Task)
}
```

### 两个新概念

**`suspend`（挂起函数）**

标记这个函数**耗时**，必须在协程里调用。Room 强制要求——如果你在主线程直接调，它会直接抛异常阻止你。

好处是：调用时写起来像同步代码，不用写回调。

```kotlin
lifecycleScope.launch {          // 开一个协程
    val task = dao.getTaskById(1)  // 像普通函数一样写，但实际在后台线程
}
```

**`Flow`（数据流）**

可以理解成「会自动推送新值的列表」。

| | 普通 `List` | `Flow<List<Task>>` |
|---|---|---|
| 取一次 | 拿到当时的快照 | — |
| 数据库变化后 | **不会通知你** | **自动推送新数据** |

这就是"增删改后列表自动刷新"的实现方式，**不需要手动调 `loadTasks()`**。

对比一下：

```kotlin
// 普通查询：查一次就完了，之后数据库变了你不知道
fun getAllTasks(): List<Task>

// Flow：数据库一变，collect 的地方会收到新列表
fun getAllTasks(): Flow<List<Task>>
```

⚠️ 评分表「增删改查后列表自动刷新」那 1 分，靠的就是 `Flow`。

## 六、第 4 步：建 AppDatabase

新建 `data/AppDatabase.kt`（**注意拼写是 Database，不是 Datebase**）：

```kotlin
package com.example.todo_list.data

import android.content.Context
import androidx.room.Database
import androidx.room.Room
import androidx.room.RoomDatabase

@Database(entities = [Task::class], version = 1, exportSchema = false)
abstract class AppDatabase : RoomDatabase() {

    abstract fun taskDao(): TaskDao

    companion object {
        @Volatile
        private var INSTANCE: AppDatabase? = null

        fun getInstance(context: Context): AppDatabase {
            return INSTANCE ?: synchronized(this) {
                INSTANCE ?: Room.databaseBuilder(
                    context.applicationContext,
                    AppDatabase::class.java,
                    "todo_database"
                ).build().also { INSTANCE = it }
            }
        }
    }
}
```

### 几个关键点

| 写法 | 原因 |
|---|---|
| `abstract class` | Room 会帮你生成实现类，你只写声明 |
| `abstract fun taskDao()` | 同样由 Room 实现 |
| 单例 + `@Volatile` + `synchronized` | **避免创建多个数据库实例**（多个实例会导致数据不一致、连接泄漏） |
| `context.applicationContext` | 用 Application 的 Context，避免持有 Activity 导致内存泄漏 |
| `version = 1` | 以后加字段要 +1，否则崩溃 |
| `exportSchema = false` | 不导出表结构文件（学习阶段用不上，能省掉警告） |

```kotlin
package com.example.todo_list.data

import android.content.Context
import kotlinx.coroutines.flow.Flow

object TaskRepository {

    private lateinit var taskDao: TaskDao

    // 在 MainActivity.onCreate 里调用一次
    fun init(context: Context) {
        taskDao = AppDatabase.getInstance(context).taskDao()
    }

    fun getTasks(): Flow<List<Task>> = taskDao.getAllTasks()

    suspend fun getTaskById(id: Long): Task? = taskDao.getTaskById(id)

    suspend fun addTask(task: Task): Long = taskDao.insertTask(task)

    suspend fun updateTask(task: Task) = taskDao.updateTask(task)

    suspend fun deleteTask(task: Task) = taskDao.deleteTask(task)
}
```

**变化对比**：

| 方法 | 第一步（内存） | 第二步（Room） |
|---|---|---|
| `getTasks()` | `List<Task>` | `Flow<List<Task>>` |
| `getTaskById()` | 同步 | `suspend` |
| `addTask()` | 同步 | `suspend` |
| `updateTask()` | 同步 | `suspend` |
| `deleteTask()` | 同步 | `suspend` |

**⚠️ 别忘了初始化**：在 `MainActivity.onCreate` 里加一行（要在任何 Fragment 用之前）：

```kotlin
override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)
    TaskRepository.init(this)      // ← 加这一行，且必须在 setContentView 之前或之后都行，但要在 Fragment 创建前
    binding = ActivityMainBinding.inflate(layoutInflater)
    setContentView(binding.root)
    // ...
}
```

## 八、第 6 步：改造 TaskListFragment

原来是：

```kotlin
override fun onResume() {
    super.onResume()
    loadTasks()          // 手动刷新
}

private fun loadTasks() {
    val tasks = TaskRepository.getTasks()
    taskAdapter.submitList(tasks)
    binding.emptyTextView.visibility = ...
}
```

改成用 Flow 自动收集：

```kotlin
override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
    super.onViewCreated(view, savedInstanceState)
    setupRecyclerView()
    observeTasks()          // ← 新增

    binding.addTaskFab.setOnClickListener {
        TaskEditActivity.startUI(requireContext())
    }
}

private fun observeTasks() {
    viewLifecycleOwner.lifecycleScope.launch {
        repeatOnLifecycle(Lifecycle.State.STARTED) {
            TaskRepository.getTasks().collect { tasks ->
                taskAdapter.submitList(tasks)
                binding.emptyTextView.visibility =
                    if (tasks.isEmpty()) View.VISIBLE else View.GONE
            }
        }
    }
}
```

需要的 import：

```kotlin
import androidx.lifecycle.Lifecycle
import androidx.lifecycle.lifecycleScope
import androidx.lifecycle.repeatOnLifecycle
import kotlinx.coroutines.launch
```

**`onResume` 里的 `loadTasks()` 可以删掉了**——Flow 会自动推送。

### 为什么用 `repeatOnLifecycle(STARTED)`

Fragment 的 View 销毁后（比如切到设置页），如果还在 collect，会浪费资源甚至崩溃。`repeatOnLifecycle(STARTED)` 表示：

- 页面可见时 → 开始收集
- 页面不可见 → **自动停止收集**
- 页面重新可见 → 自动恢复

⚠️ 必须用 `viewLifecycleOwner`（不是 `lifecycleOwner`）——因为 Fragment 的 View 生命周期和自身不一样长。

### 勾选 CheckBox 的地方也要改

```kotlin
onCheckedChange = { task, isChecked ->
    viewLifecycleOwner.lifecycleScope.launch {          // ← 包一层协程
        TaskRepository.updateTask(task.copy(isCompleted = isChecked))
    }
    // 不用再调 loadTasks()，Flow 会自动推
}
```

## 九、第 7 步：改造 TaskEditActivity

`saveTask()` 里所有数据库操作都是 `suspend`，要包进协程：

```kotlin
private fun saveTask() {
    val title = binding.titleEditText.text?.toString()?.trim().orEmpty()
    if (title.isEmpty()) {
        binding.titleInputLayout.error = getString(R.string.msg_title_required)
        return
    }
    binding.titleInputLayout.error = null

    val description = binding.descriptionEditText.text?.toString()?.trim().orEmpty()
    val isCompleted = binding.completedCheckBox.isChecked

    lifecycleScope.launch {                              // ← 新增
        if (taskId != NO_TASK_ID) {
            TaskRepository.updateTask(Task(taskId, title, description, isCompleted))
        } else {
            TaskRepository.addTask(
                Task(title = title, description = description, isCompleted = isCompleted)
            )
        }
        Toast.makeText(this@TaskEditActivity, R.string.msg_save_success, Toast.LENGTH_SHORT).show()
        finish()
    }
}
```

⚠️ 两个细节：

1. `lifecycleScope.launch { }` 包住数据库操作
2. 协程里的 `this` 变了，Toast 要用 `this@TaskEditActivity`

**`setupEditMode()` 也要改**（它调了 `getTaskById`）：

```kotlin
private fun setupEditMode() {
    lifecycleScope.launch {
        val task = TaskRepository.getTaskById(taskId)
        if (task == null) {
            Toast.makeText(this@TaskEditActivity, R.string.msg_task_not_found, Toast.LENGTH_SHORT).show()
            finish()
            return@launch          // ⚠️ 协程里用 return@launch，不是 return
        }
        supportActionBar?.title = getString(R.string.title_edit_task)
        binding.titleEditText.setText(task.title)
        binding.descriptionEditText.setText(task.description)
        binding.completedCheckBox.isChecked = task.isCompleted
    }
}
```

⚠️ **协程里 `return` 要写成 `return@launch`**，直接写 `return` 会编译报错。

需要 import：

```kotlin
import androidx.lifecycle.lifecycleScope
import kotlinx.coroutines.launch
```

## 十、第 8 步：改造 TaskDetailActivity

用 `taskId` 的地方都要进协程。涉及 `setupDetail()`、`toggleComplete`、删除。

`setupDetail()` 建议改成收集 Flow（这样详情页也能自动刷新）：

```kotlin
private fun observeTask() {
    lifecycleScope.launch {
        repeatOnLifecycle(Lifecycle.State.STARTED) {
            TaskRepository.getTasks().collect { tasks ->
                val task = tasks.find { it.id == taskId }
                if (task == null) {
                    Toast.makeText(this@TaskDetailActivity, R.string.msg_task_not_found, Toast.LENGTH_SHORT).show()
                    finish()
                    return@collect
                }
                renderTask(task)
            }
        }
    }
}
```

这样 `onResume` 里的 `setupDetail(taskId)` 可以删掉，标记完成后也不用手动刷新。

.setPositiveButton("确定") { _, _ ->

## 十二、常见错误

| 报错 | 原因 | 解决 |
|---|---|---|
| `KSP version not found` | KSP 与 Kotlin 版本不匹配 | 确认 Kotlin 1.9.24 → KSP 1.9.24-1.0.20 |
| `lateinit property taskDao has not been initialized` | 忘了调 `TaskRepository.init()` | 在 MainActivity.onCreate 加 |
| `Cannot access database on the main thread` | 在主线程调了 Room | 包进 `lifecycleScope.launch { }` |
| `'return' is not allowed here` | 协程里用了裸 `return` | 改成 `return@launch` |
| `Unresolved reference: taskDao()` | Database 没声明抽象方法 | 加 `abstract fun taskDao(): TaskDao` |
| 编译报 schema 导出警告 | `exportSchema` 默认 true | 设成 `false` |
| 保存后列表没刷新 | `getTasks()` 返回的是 `List` 不是 `Flow` | 检查 Dao 返回类型 |
| 编辑变成新增 | 第零节的 `Long?` Bug | 改参数类型为非空 `Long` |
